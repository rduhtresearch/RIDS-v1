# RIDS-v1

## Current first-time setup

Follow these steps the first time you run the app on a laptop.

1. Install R and RStudio.
2. Open the project in RStudio.
3. Open `R/SETUP/new_setup.R`.
4. Update these values so they match your local machine or shared drive:
   - `DB_DIR`
   - `ICT_UPLOAD_DIR`
   - `EDGE_OUTPUT_DIR`
5. Run the full `R/SETUP/new_setup.R` script.

The setup script will:
- install missing R packages
- create `config.R`
- create the required folders
- initialise the DuckDB database

6. Open `app.R` and run the app.
7. On first launch, the login screen will show the bootstrap form.
8. Create the first admin account in the app.
9. Sign in with that account.

## How configuration works

- `config.R` is generated by `R/SETUP/new_setup.R`.
- `global.R` loads `config.R` and opens the DuckDB connection on app startup.
- The app will stop at launch if `config.R` does not exist yet.

## Shared-drive recommendation

For the current DuckDB version, a practical layout is:

- local laptop copy of the repo for the app code
- shared drive folder for the `.duckdb` file
- shared drive folder for uploads
- shared drive folder for outputs

That means each laptop runs its own local Shiny app, but all laptops can point at the same shared data locations.

Example structure:

- `S:\RIDS\app\` or `\\server\share\RIDS\app\release\`
- `S:\RIDS\data\RIDS.duckdb`
- `S:\RIDS\uploads\`
- `S:\RIDS\outputs\`

## Important note about DuckDB

DuckDB is fine for early setup and light use, but a shared `.duckdb` file on a network drive is not the best long-term multi-user architecture.

If multiple users may be active at the same time, the better target design is:

- app code on each laptop or on a central Shiny host
- SQL Server for the database
- shared drive only for file-based imports/exports if still needed

## Re-running setup

- If you need to change paths later, update `R/SETUP/new_setup.R` and run it again.
- Do not edit `config.R` manually unless you intentionally want to bypass the setup script.
